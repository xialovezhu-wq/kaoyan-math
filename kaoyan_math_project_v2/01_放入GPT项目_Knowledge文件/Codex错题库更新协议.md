# Codex错题库更新协议

本协议用于把 GPT 的“模式 A”结果同步到 Codex 中的历史错题库。Codex 不负责重新讲题，负责维护“错题 - 方法卡 - 动作断点 - 复习提醒”的索引。

## 一、接收条件

只有当用户明确说“同步 Codex / 生成 Codex 更新指令 / 更新错题库 / 更新历史错因”时，才生成或执行 Codex 更新。普通模式 A 不自动入库。

## 二、禁止事项

- 没有用户题号时，不自动编造题号。
- 不覆盖用户原笔记，只追加“动作断点分析”。
- 不改变图片标准答案。
- 不把“看懂解析”判定为“已经掌握”。
- 未收到写入成功回执，不能说“已入库”。

## 三、Codex 更新载荷格式

```json
{
  "question_id": "若用户给了题号则填写；否则写 待用户确认",
  "subject": "高等数学/线性代数",
  "module": "二级模块",
  "target_O": "本题目标：计算/证明/判断/求参/求范围/判敛散等",
  "trigger_signal": "题面中触发方法论的信息",
  "method_card_id": "对应方法卡ID",
  "should_think": "看到该信息本应想到的方法",
  "missing_action": "实际漏掉的具体动作",
  "error_type": "知识缺口/目标识别断点/触发信息遗漏/方法论调取失败/动作链断裂/条件检查遗漏/分类讨论遗漏/收尾验证遗漏/计算错误",
  "next_reminder": "看到____，先____，再____。",
  "mastery_score": "0-5 或 待判断",
  "historical_search_keywords": ["模块", "触发词", "方法卡ID", "漏掉动作"],
  "suggested_codex_action": "新增/合并/更新历史错因/增加复习提醒/待人工复核"
}
```

## 四、历史错题合并规则

1. 先按 `method_card_id` 查历史错题。
2. 再按 `trigger_signal + missing_action + error_type` 查重复。
3. 若动作断点相同：不要新增重复错因，在原错题下追加“重复出现记录”。
4. 若知识模块相同但动作断点不同：更新该模块的错因网络。
5. 若标准答案与 GPT 解析冲突：以图片标准答案为准，标记“需人工复核”。

## 五、Codex 复习提醒规则

每次更新必须产生一句 10-30 字提醒：

“看到____，先____，再____。”

例：

- 看到级数判敛，先查通项极限，再选判别法。
- 看到幂级数，先求收敛区间，再单独查端点。
- 看到非齐次方程组，先判增广秩，再讨论解。
