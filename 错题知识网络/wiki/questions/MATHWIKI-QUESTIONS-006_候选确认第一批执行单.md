# MATHWIKI-QUESTIONS-006 候选确认第一批执行单

本页从 [[错题知识网络/wiki/questions/MATHWIKI-QUESTIONS-005_候选用户确认清单|MATHWIKI-QUESTIONS-005]] 中抽出第一批最值得优先确认的候选。它不是正式错题卡，不写 `错题卡/*.md`，不写回滚 JSON；作用是把 N5 的 15 个待确认入口压缩成一组可以直接回复的确认任务。

M144 更新：第一批候选的正式化前置检查已拆到 [[错题知识网络/wiki/questions/MATHWIKI-QUESTIONS-007_候选正式化前置检查清单|MATHWIKI-QUESTIONS-007 候选正式化前置检查清单]]。你确认某个候选后，系统先按 Q007 做查重、预检和边界判断，再决定是否改正式错题卡。

## 使用方式

如果你只想最快推进，直接复制下面任意一条并补充你的第一卡点：

> `CAND-0014/0015` 迁移为新的 GS 正式卡；我的第一卡点是：……

> `CAND-0012/0013` 以 `CAND-0012` 为主入口；这是我的错题；我的第一卡点是：……

> `CAND-0003` 是我的错题；我的第一卡点是：……

> `CAND-0001` 是我的错题；我的第一卡点是：……

> `CAND-0011` 我能补正确解析/本人卡点：……

如果你确认“不是我的错题”，也可以直接回复：

> `CAND-000X` 不是我的错题，只保留为视觉来源或同型题候选。

## 状态约束

- 以上候选确认前都不能直接转正式错题卡。
- 用户确认后，仍需按正式入库流程运行 preflight、查重、建卡或更新旧卡、rebuild 和 closeout。
- 如果用户只确认题目身份但没说第一卡点，仍停留在 candidate/confirmed 层，不写个人 `wrong_point`。
- 若确认“不是本人错题”，对应候选只保留来源证据或同型题候选，不进入回滚。

## 下一步动作映射

| 用户回复类型 | 系统动作 |

| 确认是本人错题 + 给出第一卡点 | 切换到正式错题入库流程，先 `intake_preflight.py` 查重，再决定新建或更新。 |
| 确认不是本人错题 | 候选保持来源证据，不建卡；必要时在台账中改为 dropped 或 source_retained。 |

| `CAND-0011` 补正确解析 | 先复核解析是否对应 `57718`，再决定是否新建 GS 卡。 |
